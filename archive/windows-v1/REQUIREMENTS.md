# SendToCmd 现有功能需求文档

> 基线日期：2026-10-03。本文依据当前 `SendToCmd.cs` 和 `README.md` 整理，描述**已经实现的行为**，供后续选择跨平台方案时对照；不代表新增功能需求。

## 1. 产品定位与使用场景

SendToCmd 是一个用于保存和逐行发送命令的桌面记事本。用户先在外部终端中通过 SSH、串口等方式连接设备，再将 SendToCmd 绑定到该终端窗口。用户可手动发送当前行，也可设定起止行，按固定间隔自动发送。每行发送后都自动输入一次回车，空行仅输入回车。

当前交付形态是适用于 **64 位 Windows 10/11** 的独立 `SendToCmd.exe`，使用 Windows 自带的 .NET Framework 4.x，无需 Python。当前版本没有 macOS 或 Linux 可执行程序。

## 2. 界面与编辑

| 编号 | 已实现需求与可验收行为 |
| --- | --- |
| UI-01 | 窗口标题显示 `SendToCmd — 文件名`；新文档显示 `Untitled`／`未命名`，未保存修改时在名称前显示 `*`。 |
| UI-02 | 顶部同一行放置“文件”“编辑”“设置”菜单，以及目标名称和“绑定终端”十字准星。目标名称过长时保持单行省略，鼠标悬停可查看完整名称。 |
| UI-03 | 中央为纯文本编辑区，按行显示命令；左侧显示行号。点击文本行或行号后，该行以浅色阴影标示为当前行；不自动换行。 |
| UI-04 | 底部同一行显示状态、发送间隔、自动发送勾选框和纸飞机发送按钮。悬停发送按钮时提示当前操作及 F8 快捷键；自动发送期间按钮变为停止图形。 |
| UI-05 | 通过清晰的多尺寸程序图标和 DPI 感知界面适配 Windows 缩放显示。 |

## 3. 文本文件与编辑命令

| 编号 | 已实现需求与可验收行为 |
| --- | --- |
| FILE-01 | “文件”菜单提供新建、打开、保存、另存为、退出；“编辑”菜单提供撤销、剪切、复制、粘贴、全选、查找。 |
| FILE-02 | 支持打开 UTF-8 文本文件（有或无 UTF-8 BOM）；保存为无 BOM 的 UTF-8 文本。打开失败或保存失败时显示错误。 |
| FILE-03 | 新建、打开其他文件或退出时，如当前文档有未保存修改，则提示保存、不保存或取消；取消时保留当前文档。 |
| FILE-04 | 查找支持“查找下一个”，到达文末后从文首继续；找不到时提示。 |
| FILE-05 | 修改文本后标记为未保存，并清除自动发送的起点和终点标记。 |

快捷键：新建 `Ctrl+N`、打开 `Ctrl+O`、保存 `Ctrl+S`、另存为 `Ctrl+Shift+S`、撤销 `Ctrl+Z`、剪切 `Ctrl+X`、复制 `Ctrl+C`、粘贴 `Ctrl+V`、全选 `Ctrl+A`、查找 `Ctrl+F`。

## 4. 目标窗口绑定

| 编号 | 已实现需求与可验收行为 |
| --- | --- |
| TARGET-01 | 用鼠标左键按住右上角十字准星，拖到目标窗口，松开后绑定鼠标所在位置对应的顶层窗口，并显示窗口标题。 |
| TARGET-02 | 不接受本程序窗口、不可见窗口或没有标题的窗口。拖动取消或未选中可用窗口时，保留原有绑定。 |
| TARGET-03 | 每次发送前确认绑定窗口仍然存在且属于原进程；目标未绑定或已关闭时，不发送并提示重新绑定。 |
| TARGET-04 | 发送前尝试恢复最小化的目标窗口并使其成为前台窗口；若未成功获得焦点，则取消该次发送。用户须预先选中终端中正确的标签页或输入区域。 |

绑定的是当前运行期间的一个外部窗口；重新启动软件后需要重新绑定。

## 5. 手动发送

| 编号 | 已实现需求与可验收行为 |
| --- | --- |
| SEND-01 | 默认不勾选“自动发送”。点击纸飞机按钮，或在 SendToCmd 窗口有焦点时按 `F8`，发送当前阴影所指行的**整行内容**，随后输入回车。 |
| SEND-02 | 空行也参与发送，仅输入一次回车。发送成功后状态显示 `Sent line N`／`已发送第N行`，当前行移到下一行；已在最后一行时保持在该行。 |
| SEND-03 | 单行超过 4096 个 UTF-16 字符单元，或含制表符等控制字符时，拒绝发送并提示；发送失败时不自动前进到下一行。 |
| SEND-04 | 使用 Windows 模拟键盘输入接口发送文字与回车，不修改剪贴板。 |

`F8` 是软件窗口内快捷键，并非系统全局热键。状态中的“已发送”表示输入已交给 Windows，不能证明终端或设备已执行命令。

## 6. 区间自动发送

| 编号 | 已实现需求与可验收行为 |
| --- | --- |
| AUTO-01 | 在左侧行号上右键，可将某行设为起点（绿点）、终点（红点），或清除两个标记。起点与终点都包含在发送范围内，也允许设在同一行。 |
| AUTO-02 | 底部间隔默认 `1.0` 秒，可按 `0.1` 秒递增，在 `0.1`～`60.0` 秒内设置。勾选“自动发送”后，点击纸飞机按钮或按 `F8` 开始；未勾选时仍执行单行发送。 |
| AUTO-03 | 启动前检查起止行顺序、目标窗口和范围内各行的长度及控制字符；不满足条件时提示，且不启动发送。 |
| AUTO-04 | 从起点到终点逐行发送，每行后自动回车，包括空行。首行在目标切换焦点后的短暂等待后发送；后续各行在上一行发送完成后，按设定间隔发送。 |
| AUTO-05 | 运行期间编辑区只读，绑定按钮、间隔输入和自动发送勾选框禁用；发送按钮显示停止图形，点击或按 `F8` 可中止。达到终点后自动结束并恢复控件。 |
| AUTO-06 | 目标关闭、失去前台焦点或输入失败时，自动发送停止并提示。新建、打开、查找、切换语言或关闭程序时，正在运行的自动发送也会停止。 |

## 7. 语言与持久化

| 编号 | 已实现需求与可验收行为 |
| --- | --- |
| LANG-01 | 提供英文和中文界面，首次启动默认英文；可从“设置 → 语言”切换，菜单、状态、提示和工具提示随之更新。 |
| LANG-02 | 语言选择保存在 `%APPDATA%\SendToCmd\language.txt`，下次启动恢复。切换语言时保留当前文本和绑定目标。 |
| DATA-01 | 命令文本仅在用户执行保存操作后写入所选文件；语言选择单独保存。绑定目标、起止行标记及自动发送间隔不作为文档内容保存。 |

## 8. 当前边界与跨平台对照重点

- 当前程序没有内置 SSH 客户端、串口连接器或终端模拟器；连接设备、选择终端输入区域由用户在外部终端完成。
- 当前程序不读取终端输出，也不判断命令执行成功与否。自动发送按时间间隔推进，不等待设备返回结果。
- 当前窗口绑定和键盘输入依赖 Windows 窗口及输入 API；Windows 版的行为不能直接等同于 macOS 或 Linux 上的实现。
- 单次仅绑定一个目标窗口、编辑一个文档；没有多标签文档或多目标并发发送。
- 后续评估跨平台方案时，应逐项确认：三平台的文本编辑与文件编码、目标选择或连接方式、单行及空行发送、区间标记与定时发送、暂停和失焦保护、快捷键、双语界面、打包与权限行为。目标绑定与输入注入是需要重点重新设计的平台相关部分。
